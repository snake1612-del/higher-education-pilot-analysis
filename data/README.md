# Локальные входные файлы

Исходные массивы хакатона и построчные производные таблицы не включаются в публичную версию. Входы автоматически создаёт `src/prepare_inputs.py` из оригинальных Excel. [Реестр](../metadata/scope_registry.json) составлен по публичным документам и распространяется отдельно от наблюдений МКП.
Директория `data/private/` исключена из Git. Не добавлять файлы данных принудительно.

## Бюджетный лист МКП

Согласно листу «методинфо» исходного Excel, массив уже ограничен головными государственными вузами с данными о суммарном бюджетном и платном приёме в каждый год 2021–2025. Предметный фон формируется внутри этой исходной пятилетней панели; он не представляет автоматически все российские вузы. Затем для каждой метрики дополнительно отбираются группы с полной допустимой историей. Условие полноты исходного массива по вузам не гарантирует полноту каждой группы и показателя.

CSV в UTF-8, разделитель `;`, первая строка — заголовок. Порядок 19 столбцов:

1. Группа подготовки.
2. Регион.
3. Вуз.
4. Профиль.
5. Пять столбцов зачисления на бюджет за 2021, 2022, 2023, 2024, 2025 годы.
6. Пять столбцов БВИ за те же годы.
7. Пять столбцов среднего балла за те же годы.

Наличие заголовка не означает сопоставление по его имени: `COPY` читает значения
по порядку. Столбец `is_pilot`, добавленный в рабочую таблицу позднее, не импортируется.
Для первоначальной шестёрки используется отдельный справочник точных имён.

Если данные уже импортированы и типизированы в `public.mkp_budget_raw`, можно
вместо CSV один раз скопировать исходные поля в новую схему:

```sql
INSERT INTO research_raw.mkp_budget
SELECT major_group, region, university, profile,
       admitted_2021::text, admitted_2022::text, admitted_2023::text,
       admitted_2024::text, admitted_2025::text,
       bvi_2021::text, bvi_2022::text, bvi_2023::text,
       bvi_2024::text, bvi_2025::text,
       ege_2021::text, ege_2022::text, ege_2023::text,
       ege_2024::text, ege_2025::text
FROM public.mkp_budget_raw;
```

Этот вариант предполагает именно указанную схему столбцов. CSV и копирование
рабочей таблицы — альтернативные способы, их нельзя выполнять подряд для одного набора.

## Реестр связей

Отдельный CSV с заголовком, разделитель `,`:

```text
university,major_group,scope,evidence_note
```

Ключ — вуз, группа и охват. `cohort2023` — основная исторически подтверждённая
когорта; `confirmed_eventual` — фиксированный подтверждённый перечень к 2025 году.
Одна связь может иметь по строке в каждом охвате. Дубликаты внутри охвата запрещены.
Реестр формируется по проверенным источникам до анализа результата. Не восстанавливать
его по наличию роста балла, приёма или БВИ. Отсутствие подтверждения не означает,
что программа не участвовала в пилоте.

## МЭВ и таблица соответствий

Для дополнительного файла `09_mev_context.sql`:

1. Выполнить его блок `CREATE TABLE`.
2. Загрузить локальный `mev_selected.csv` в `research_raw.mev_selected`: 18 столбцов
   в указанном в SQL порядке, UTF-8, разделитель `;`, заголовок.
3. Загрузить локальное соответствие `university,mev_id` в `research.mev_crosswalk`.
4. Выполнить блоки `CREATE VIEW` и `SELECT`.

Справочник ID проверяется отдельно, названия разных массивов не соединяются
по случайному совпадению подстроки. Для выбранного CSV `full_time_share`,
`bachelor_share`, `master_share` уже выражены в процентах. Поля `*_students`
представляют численности. Год мониторинга и отчётный год различаются на единицу.

`mev_selected.csv` — подготовленная локальная выборка, не исходный полный CSV МЭВ.
Прямой импорт полного массива в эту 18-столбцовую таблицу недопустим.

## Единицы МЭВ

`*_students` по областям знаний — приведённый контингент, `total_students` — общая численность. Доля инженерной области рассчитывается в сумме восьми областей знаний. Её нельзя автоматически делить на общую физическую численность студентов. Пропуск компонента делает сумму неизвестной. Сопоставление идентификаторов создаётся локально по проверенным точным именам головных организаций из `metadata/university_names.json`; неоднозначность вызывает ошибку.
