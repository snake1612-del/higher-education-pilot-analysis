# Воспроизведение и проверка

Публичный код воспроизводит основные сравнения и новые проверки аудита. Для запуска нужны разрешённые исходные Excel МКП и МЭВ организаторов хакатона. Данные нельзя скачивать из этого репозитория: они здесь не распространяются. По вопросу доступа следует обращаться к организаторам: rhec@hse.ru.

## Полный запуск

Python 3.12, PostgreSQL 18, установленный клиент psql. Зависимости фиксированы в `requirements.txt`. База должна быть новой и отдельной от рабочей базы пользователя.

```bash
python -m pip install -r requirements.txt
createdb hse_pilot_reproduction
python src/run_analysis.py --mkp /path/to/МКП.xlsx --mev /path/to/МЭВ.xlsx --dsn 'dbname=hse_pilot_reproduction user=postgres'
python src/build_figures.py
```

На macOS клиент может находиться в `/Library/PostgreSQL/18/bin/psql`: укажите путь параметром `--psql`. Подключение можно задать строкой `host=localhost port=5432 dbname=hse_pilot_reproduction user=postgres`. Пароль хранится в `.pgpass`, не включается в код или публикуемые файлы. МЭВ необязателен для основных расчётов; без `--mev` выполняется анализ МКП.

Сценарий:

0. До записи входов проверяет, что каталог результата пуст или ещё не существует, а в базе нет схем `research` и `research_raw`.
1. Извлекает бюджетный лист МКП и нужные поля МЭВ по именам столбцов; сохраняет контрольные суммы Excel.
2. Строит CSV реестра из опубликованного `metadata/scope_registry.json` и локальное соответствие ID МЭВ по проверенным точным названиям головных вузов.
3. Создаёт схемы проекта и загружает входы. Наличие прежней исходной таблицы вызывает остановку; автоматического удаления нет.
4. Выполняет подготовку, контроль качества, постоянные панели, основные запросы и проверки аудита, включая `13_presentation_checks.sql`.
5. Проверяет размеры опубликованных панелей: 16 связок / четыре вуза для баллов основной когорты, восемь / четыре для БВИ, шесть вузов в общем сравнении баллов.
6. Сравнивает результаты SQL с независимым Python-расчётом из бюджетного CSV, включая базы, охваты, два варианта весов и пересчёты БВИ после порогов. Проверяются стороны `all`, `linked` и `other_observed`, собственные изменения балла и изменения фона. Основные строки БВИ и порог 0 сверяются отдельно; дубликаты и пропуски в каждом семействе вызывают ошибку.
7. Создаёт локальные входы графиков и метаданные их состава. Графики строятся отдельной последней командой.

В `outputs/` остаются `comparisons.json`, `double_fixed.json`, `bvi_thresholds.json`, `selection_flow.json`, `panel_coverage.json`, `panel_members.json`, `linked_shares.json`, `internal_contrasts.json`, `bvi_donors.json`, `bvi_donor_members.json`, независимые расчёты, журналы SQL и `validation.json`. Это локальные производные данные, исключённые из Git. Текущий запуск сверил 635 основных независимых строк Python и четыре дополнительных набора с 757 строками SQL; 4191 числовая проверка прошла с допуском 1e−8. Проверка тождества вычислений не заменяет проверку исследовательских предпосылок.

Для повторного запуска используйте новую пустую базу **и новый пустой каталог результата**. Например:

```bash
python src/run_analysis.py --mkp /path/to/МКП.xlsx --mev /path/to/МЭВ.xlsx --dsn 'dbname=hse_pilot_reproduction_2 user=postgres' --output outputs/run_2
python src/build_figures.py --data-dir outputs/run_2/chart_data
```

Занятый каталог отвергается без изменений, даже если прежний запуск был успешным. Занятая или недоступная база обнаруживается до подготовки входов. Начатый запуск получает `run_id`, время начала и статус `running`; пойманная ошибка меняет его на `failed`, а `pass` записывается только после завершения проверок и экспорта. Старый `pass` относится только к сохранённому прежнему каталогу и его контрольным суммам. После принудительного завершения процесса статус может остаться `running`; это не подтверждение успеха.

В итоговом отчёте отдельно указаны: `comparisons` — 427 строк / 2954 проверки, `double_fixed` — 154 / 308, `bvi_thresholds` — 110 / 660. Дополнительные сверки: доли — 20 / 100; внутривузовские контрасты — 8 / 40; БВИ по числу вузов фона — 13 / 104; состав их групп — 25 / 25. Всего 757 строк SQL и 4191 числовая проверка. Основные строки БВИ и порог 0 проверяются оба, даже когда используют одну независимо рассчитанную строку.

 При смене определения материализованного представления одного `REFRESH` недостаточно; новую версию следует воспроизводить в новой базе. Для ручного маршрута см. [SQL-инструкцию](../sql/README.md).

## Проверки без закрытых данных

```bash
python -m unittest discover -s tests -v
createdb hse_pilot_fixture
python tests/sql_regression.py --dsn 'dbname=hse_pilot_fixture user=postgres'
```

Модульные тесты также намеренно подменяют основные БВИ, проверяют отсутствие и дублирование строк, пороги числа вузов фона, ошибки долей и внутривузовских компонентов, сохранность прежних файлов при повторном запуске и статус ошибки после частичной подготовки.

Вторая команда проверки требует отдельной пустой базы, не удаляет таблицы и использует только искусственные наблюдения. Проверяются смена структуры фона при неизменных баллах, отсутствие подходящего фона, отличие нуля от пропуска и остановка при неправильном составе итоговой панели. Для графиков значения вне настроенного диапазона и несовпадение размеров панели с SQL-выгрузками вызывают ошибку.

## Граница воспроизводимого расчёта

Согласно листу «методинфо» исходного Excel, массив уже ограничен головными государственными вузами с данными о суммарном бюджетном и платном приёме в каждый год 2021–2025. Предметный фон формируется внутри этой исходной пятилетней панели; он не представляет автоматически все российские вузы. Затем для каждой метрики дополнительно отбираются группы с полной допустимой историей. Условие полноты исходного массива по вузам не гарантирует полноту каждой группы и показателя.

Реестр — частичный документированный перечень связей, а не полный список фактически зачисленных на пилот. Внутри групп могут быть непилотные программы. Источники, локаторы и оговорки включены в реестр; недоступность повторного скачивания отдельных исторических страниц отмечена в исходных карточках.

Подбор ближайших аналогов по МЭВ не включён в публичный сценарий. Не следует считать его выполненным только из-за наличия описательного файла `09_mev_context.sql`. Исторический исследовательский код и его промежуточные входы сохранены отдельно локально. Они не используются как дополнительное доказательство устойчивости в обновлённом README.

Для разрешённой проверки жюри подготовлен локальный комплект: публичный код, исходные Excel, реестр, промежуточные результаты, числовые сверки и архив исторических расчётов. Комплект не публикуется и автоматически никому не отправляется. Получатель должен иметь право доступа к данным.


## Отдельное воспроизведение по исходным Excel

В предоставленном [независимом протоколе](independent_replication.md) зафиксировано воспроизведение версии `c00fc5a4` на PostgreSQL 18.6: 757 строк SQL, 4191 встроенная числовая сверка и 214 дополнительных сравнений отдельной реализацией непосредственно из Excel. Ключевые результаты v5 совпали. Дополнительный расчёт не использовал расчётные функции проекта; его код не включён в общий сценарий.

Контрольная сумма МКП в этой проверке отличается от авторского запуска, а контрольная сумма МЭВ совпадает. Обе суммы МКП сохранены в отдельном документе. Прежний `docs/validation.json` не заменяется: он описывает свой запуск и свои исходные файлы. Совпадение проверенных результатов не означает побайтовой идентичности Excel. Причина различия не установлена.

Отдельная проверка подтверждает вычисления по опубликованной методике и реестру; она не подтверждает заново каждое историческое отнесение программы к пилоту и не устанавливает причинный эффект или прямой спрос.
