Основная спецификация сохранена, чтобы изменение весов не выбиралось по удобству результата. Дополнительные варианты представлены рядом. Причинный эффект, прямой рост спроса и статистическая значимость по-прежнему не установлены.

## Повторный аудит версии 9af6a8b

1. **Основные БВИ больше не перекрываются порогом 0.** SQL-таблицы сверяются раздельно. Число и полнота ключей контролируются внутри каждого семейства. Исправленная проверка обнаружила каждую из 112 намеренных подмен: по два показателя в 56 основных строках БВИ на реальном локальном расчёте. Это проверка механизма, а не публикация исходных строк.
2. **Результаты разных запусков не смешиваются.** Непустой каталог не переиспользуется. Наличие проектных схем в базе проверяется до записи входов. Для начатого запуска фиксируются идентификатор, время и статус; пойманная ошибка сохраняет `failed`. Проверен повторный запуск на реально заполненной временной базе: прежние входы и результаты побайтово сохранились; новый каталог не создавался при занятой базе.
3. **Уточнена SQL-инструкция.** Ограничение относится к исходным и построчным производным массивам; агрегированные результаты и метаданные опубликованы.

Повторный полный запуск из тех же двух исходных Excel на PostgreSQL 18.6: 439 независимых строк Python сопоставлены с 495 строками SQL; 2662 числовые проверки прошли. Разбивка по семействам включена в [отчёт проверки](validation.json). Прежнее число 2214 не включало отдельную сверку 56 основных строк БВИ; добавлено 448 числовых проверок. Все семь итоговых числовых таблиц совпали с предыдущим запуском, включая БВИ 48 → 79. Исследовательские выводы и изображения менять не потребовалось.

Пройдены 12 модульных тестов, SQL-регрессии и проверки повторного запуска. Новые модульные тесты используют только искусственные данные и доступны без исходных Excel.
